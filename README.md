# NePropusti

## Status

**VALIDATE BEFORE BUILDING**

NePropusti is a validation-first product thesis, not an authorized super-app build.

The product abstraction remains:

> **A structured Watch platform where a user or partner defines a condition, NePropusti observes trusted state, detects a meaningful transition, verifies it, and alerts only when action becomes worthwhile.**

```text
watch -> observe -> verified transition -> useful alert -> action
```

## Current leading validation wedge — 2026-09-16

**Merchant-distributed size / variant / restock Watch**

The first commercial hypothesis is intentionally narrow:

```text
merchant product page
  -> hosted/embedded Watch
  -> user requests size/variant/restock condition
  -> trusted merchant state transition
  -> service alert
  -> attributable return action
  -> measurable recovered revenue
```

Initial ICP hypothesis: mid-market Serbian fashion/footwear ecommerce merchants with meaningful size/variant stock churn and incomplete item-level alert automation.

## Product-shape hypothesis

**Hosted/Embedded Watch + hybrid B2B2C**

For the first pilot, the merchant should retain the customer relationship by default. NePropusti provides the Watch/rule/delivery/attribution service. A portable cross-site NePropusti identity is optional and must be earned through real multi-merchant user behavior.

No mandatory NePropusti account is required for the first pilot.

## Price / open-data role

Serbia's 2026 machine-readable retail-price infrastructure remains useful data/timing context, but it is **not a moat and no longer the primary wedge**.

Tprice, Cenoteka, Idealno, ePonuda and merchant-native tools already cover substantial price-comparison/history/threshold territory.

Price Truth / target-price can be tested later as supporting Watch conditions after the first merchant-distributed trigger proves value.

## Secondary validation tracks

- **Sport + where-to-watch** remains a lower-cost retention experiment, not a live-score product.
- **NePropusti Pro / deadline alerts** is a separate adjacency hypothesis and must not be mixed into the consumer-commerce MVP without evidence.
