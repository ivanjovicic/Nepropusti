## Phase 1 — Merchant size/variant/restock validation
**NOW — highest priority**

- select ~20 strong-fit Serbian fashion/footwear/specialist merchants;
- manually verify their current wishlist/restock/CRM alternatives;
- pitch one concrete hosted/no-code `SIZE_AVAILABLE` / `BACK_IN_STOCK` Watch surface;
- identify ≥5 credible pilot commitments;
- publish ≥3 real pilot surfaces if commitments exist;
- recruit qualified users through those surfaces;
- measure watch creation, trigger quality, attributable return/action and support burden.

Do not build a WooCommerce plugin before repeated pilot integration proves it is needed.

## Phase 2 — User behavior + partner economics
**NOW in parallel with Phase 1**

Measure:
- qualified watch creation;
- useful triggered action;
- completed/expired watches;
- false/stale/late alerts;
- return click/conversion proxy;
- why merchant uses NePropusti instead of a €49–59 plugin or existing CRM;
- owner of source/data correctness;
- onboarding/support time per partner.

Price thresholds may be tested as secondary conditions, not as the primary wedge.

## Phase 3 — Open-price/data audit
**SUPPORTING TRACK**

Continue NP-VAL-001 to establish source quality and legal/reuse truth for later price conditions.

Do not treat public price data as product moat.

## Phase 4 — Sports concierge validation
**LOWER-COST PARALLEL TRACK**

- narrow teams/players/events;
- manually/semi-automatically test where-to-watch workflow;
- establish broadcaster data rights/freshness before automation;
- keep payer model explicit.

## Phase 5 — Alert-quality proof
Automate only enough of the winning trigger/source path to measure reliability.

Prefer merchant canonical product/variant IDs and webhooks/feeds over inferred scraping for the first B2B wedge.

## Phase 6 — First monetization
Ask for real payment/contract after attributable partner value exists.

Candidate validation prices may include €99–199/month or outcome-linked pricing, but these are hypotheses until a real payer agrees.

## Phase 7 — Narrow MVP
Only after user, partner, quality and monetization gates sufficiently pass.

## Phase 8+ — Optional expansion
- portable cross-site identity only after multi-merchant behavior exists;
- second vertical -> G8;
- native mobile -> G9;
- region -> G10;
- plugin/SDK/white-label only after repeated partner demand.

A failed gate can cause stop, split-brand decision, narrow utility outcome, or pivot.
